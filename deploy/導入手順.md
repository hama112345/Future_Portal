# 診断ツール ポータル ― 公開手順（GitHub Pages）

危機管理アセスメントとキャッシュフロー診断を、1つのポータルから選んで使えるようにした版です。
上から順に進めれば、1時間ほどで現場で試せる状態になります。

---

## 0. 今回の版でできること・できないこと

| | 内容 |
|---|---|
| できる | ポータルで担当者名を入れ、2つの診断を選んで使う |
| できる | 結果を**PDFで保存**（どちらの診断も、回答の控えが一緒に載ります） |
| できる | 同意のチェックを入れないと診断を始められない |
| **止めている** | **スプレッドシートへの回答の記録**（GASの `RECORD: false`） |
| まだできない | アクセス制限。GitHub Pagesは**誰でも開けるURL**です |

> 専用サーバーが用意できたら、`RECORD: true` に戻し、アクセス制限付きの領域へ移します。
> 戻し方は最後の「あとで元に戻すとき」にあります。

---

## 1. フォルダの構成

```
（リポジトリ直下）
├── index.html          ← ポータル（担当者を選んで診断へ）
├── ra/
│   ├── index.html      ← 危機管理アセスメント v2.0.1
│   └── result_*.png    ← 結果の動物イラスト 12枚
├── cf/
│   └── index.html      ← キャッシュフロー診断 v1.6.4
├── gas/                ← GASに貼り付けるコード（リポジトリに上げなくてもOK）
│   ├── 危機管理アセスメント_Code.gs
│   └── キャッシュフロー診断_Code.gs
└── deploy/             ← この手順書など（同上）
```

`gas/` と `deploy/` はページの表示には使いません。上げても害はありません。

---

## 2. GASを設置する（2本）

判定（配点・ランク・12タイプの文言など）はGAS側にあります。
**GASを先に用意しないと、ページを開いても結果が出ません。**

### 2-1. 危機管理アセスメント（新規）

1. Googleドライブで新しいスプレッドシートを作る（名前は「危機管理アセスメント_回答」など）
2. **拡張機能 → Apps Script** を開き、既定の `myFunction` を全部消す
3. `gas/危機管理アセスメント_Code.gs` の中身をすべて貼り付けて保存
4. 冒頭の `CONFIG` を確認する

```javascript
const CONFIG = {
  SHEET_ID:   '',
  SHEET_NAME: 'responses',
  TOKEN:      'test',      // ra/index.html の CONFIG.token と同じ文字列にする
  RECORD:     false        // ← 今回はこのまま（記録しない）
};
```

5. **デプロイ → 新しいデプロイ → 歯車 → ウェブアプリ**

| 項目 | 設定値 |
|---|---|
| 次のユーザーとして実行 | **自分** |
| アクセスできるユーザー | **全員** |

6. 発行された `https://script.google.com/macros/s/AKfy.../exec` をコピー
7. そのURLをブラウザで開き、`{"ok":true,"msg":"endpoint alive"}` が出れば疎通OK

> `RECORD: false` のときは `testAppend` を実行する必要はありません。
> （記録を再開するときだけ使います）

### 2-2. キャッシュフロー診断（既存のものを更新）

すでに動いているGASがあります。**コードの差し替えと再デプロイだけ**です。

1. いまのGASプロジェクトを開く
2. `Code.gs` の中身を、`gas/キャッシュフロー診断_Code.gs` の内容ですべて置き換えて保存
   - `CONFIG` に `RECORD: false` が増えています
3. **デプロイ → デプロイを管理 → 鉛筆アイコン → バージョン「新バージョン」→ デプロイ**
   - **既存の `/exec` URLはそのまま使えます**（HTML側の書き換えは不要）

> この再デプロイをしないと、記録が止まりません。忘れずに。

## 3. ra/index.html に送信先を書き込む

`ra/index.html` を開き、`<script>` の冒頭にある `CONFIG` を書き換えます。

```javascript
const CONFIG = {
    endpoint:       'https://script.google.com/macros/s/AKfy.../exec',  // 2-1でコピーしたURL
    token:          'test',          // 2-1のTOKENと完全に同じ文字列
    appVersion:     'v2.0.2',
    consentVersion: '2026-10-08'
};
```

`cf/index.html` は**書き換え不要**です（送信先は既に入っています）。

## 4. GitHubに上げて公開する

1. GitHubで **新しいリポジトリを作成**（例：`future-portal`）
   - Public で作成します（Privateだと無料プランではPagesを公開できません）
2. リポジトリの画面で **Add file → Upload files**
3. このフォルダの中身を**フォルダごとドラッグ＆ドロップ**して Commit
   - `index.html` がリポジトリの**直下**に来ていることを確認してください
4. **Settings → Pages** を開く
   - Source: `Deploy from a branch`
   - Branch: `main` / `/ (root)` → Save
5. 1〜2分待つと URL が表示されます

```
https://（ユーザー名）.github.io/future-portal/
```

### 動作確認

| 見るところ | 期待する動き |
|---|---|
| ポータル | 担当者名を入れると、下のカードのリンクに名前が付く |
| 危機管理アセスメント | 同意のチェックを入れるまでボタンが押せない |
| 〃 | 16問に答えると動物のイラストと結果が出る |
| 〃 | 「結果をPDFで保存する」で、結果＋回答の控えが出る |
| キャッシュフロー診断 | 同意 → 入力 → 結果が出る |
| 〃 | 「結果と回答の控えをPDFで保存」で詳細シートが出る |
| 両方 | PDFの上に**実施日と担当者名**が入っている |
| スプレッドシート | **行が増えていない**（記録が止まっている確認） |

ブラウザの印刷画面では、送信先を「**PDFに保存**」にしてください。

## 5. 担当者ごとのブックマーク

ポータルのURLに担当者名を付けて配ると、開いた時点で名前が入っています。

```
https://（ユーザー名）.github.io/future-portal/?staff=浜西
```

これをスマホのホーム画面に追加しておくと、現場では**開く → ツールを選ぶ**の2手で始められます。

---

## 6. 現場で使うときの注意

- このURLは**誰でも開けます**。お客様の氏名・住所・連絡先は、どちらの診断にも入力しないでください
- 回答はサーバーに残りません。**記録はPDFのみ**です
- PDFはお客様の情報です。担当者の端末または社内の指定場所に保管してください
- お客様からPDFの破棄を求められたら、保存したファイルを削除してください

## 7. あとで元に戻すとき

### 7-1. 回答の記録を再開する

1. GAS 2本の `CONFIG.RECORD` を `true` に変える
2. **新バージョンとして再デプロイ**する
3. 危機管理アセスメント側は、先に `testAppend` を1回実行して見出し行を作る
4. 同意文を「サーバーに保存していません」から元の文面（保存期間5年・削除依頼先）に戻す
   - `ra/index.html` と `cf/index.html` の「データの保存について」の節
   - `consentVersion` の日付も上げる

### 7-2. 自社サーバーへ移す

`public_html` の下に WordPress とは別のディレクトリを作り、同じ構成のまま置きます。

```
public_html/
└── shindan/
    ├── index.html
    ├── ra/（index.html と result_*.png）
    ├── cf/（index.html）
    ├── .htaccess   ← deploy/htaccess-sample.txt をリネームして設置
    └── .htpasswd
```

Basic認証は、サーバーのコントロールパネルの「アクセス制限」機能が一番簡単です
（エックスサーバー：「アクセス制限」／さくら：「ディレクトリのパスワード制限」）。
手で設定する場合は `deploy/htaccess-sample.txt` を参照してください。

> WordPressの固定ページに貼り付ける方法は避けてください。
> 各HTMLは独自のCSSを内蔵しているため、テーマのCSSと衝突してレイアウトが崩れます。

### 7-3. 本番前に必須

- `TOKEN` を `test` から**30文字以上のランダムな文字列**へ変更し、HTML側とGAS側を一致させる
- 同意文の「ご担当のコンサルタントまで」を、必要なら正式な社名・問い合わせ先へ差し替える
- ポータルの「社内利用・公開前テスト版」の表記を外す
